查看 4 个输入
4

Flow/token2wav 的四个核心数据输入： 目标语音 Token、参考语音 Token、参考 Mel、说话人 Embedding。 token_offset 和 finalize 是可选流式控制量，不是第五、第六个声学条件。

Flow 的四个核心输入

对应当前 forward_token2wav(...) 的四个必需数据张量

1

目标语音 Token

target_speech_tokens

由 Speech LLM 根据目标文本自回归生成，携带目标内容、发音和高层韵律信息。

2

参考语音 Token

prompt_speech_tokens

由参考音频提取，并裁剪到与参考 Mel 严格对齐；为 Flow 提供参考语音上下文。

3

参考 Mel

prompt_speech_feat

24 kHz、80 维 Mel 特征，以 2:1 的帧数比例和参考 Token 对齐，提供细粒度声学条件。

4

说话人 Embedding

prompt_spk_embedding

CAMPPlus 提取的 192 维说话人向量，提供稳定的身份和音色条件。

不要混淆的三层接口

同一个“Flow”在不同代码层看到的输入数量并不相同

01 · Triton token2wav API

4 个核心输入 + 2 个可选控制量

四个数据张量之外，流式推理可附加 token_offset 与 finalize。前者用于裁掉已经生成的 Mel，后者标记中间块或最终块。

02 · flow.inference

内部自动补充长度张量

Python Backend 根据张量 shape 构造 token_len、 prompt_token_len 和 prompt_feat_len，调用方不需要上传。

03 · TensorRT estimator

更底层是 x / mask / mu / cond

这是 Flow decoder estimator 内部的 TensorRT 引擎接口，已经是经过 Flow 前处理后的张量，不能当成对外 token2wav 输入来描述。

另一个容易漏掉的细节：LLM 使用完整的 prompt_speech_tokens_for_llm； Flow 使用与参考 Mel 对齐后的 prompt_speech_tokens。两者来源相同，但长度不一定相同。
